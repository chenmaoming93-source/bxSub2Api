## 1. 本次修订结论

当前实现的主要问题不是“配色不同”，而是页面没有按 Demo 的信息架构和诊断路径落地。v2 以原始 Demo 为视觉与交互合同，以 v1.8 修订结论为真实数据合同。

页面目标不变：

1. 5 秒内判断平台是否健康。
2. 30 秒内从趋势或热度定位到具体对象。
3. 2 分钟内形成用户、分组、路由别名、模型账号和错误阶段的只读诊断结论。

页面仍为纯只读，不包含切流、容量写入、阈值应用、回滚或审计处置。

## 4. 全局筛选语义

同一观测台页面内所有组件共用同一筛选上下文：

```text
user_ids
group_ids
route_aliases
account_ids
department
only_pressure
```

规则：

- ID 是筛选参数，展示名不进入 URL 或 SQL 条件。
- 四个维度先各自取并集，再在维度间取交集。
- 当前筛选无路径结果时，所有组件显示空态，不显示伪造的 0 曲线。
- 切换聚合维度只改变 GROUP BY；切换观测对象改变 WHERE。
- 筛选变化后取消旧请求，防止慢响应覆盖新结果。
- 点击排行、热力图、链路和告警时，统一写入全局筛选或链路选中项。

## 5. 数据真实性规则

- Token 当前累计取 tokenstat 投影。
- 请求、成功、最终失败、耗时、TTFT 取请求聚合事实。
- 请求数必须满足：`请求数 = 成功数 + 最终失败数`。
- 最终客户端失败率、业务限制率、SLA 错误率、上游错误率分开返回。
- 请求平均耗时 = `Σ duration_ms / duration 非空样本数`；首 Token 平均耗时 = `Σ first_token_ms / TTFT 非空样本数`。跨桶或跨维度时，先累加分子与样本数，再相除；不能对桶平均值再次平均。
- P95 可以作为详情或扩展诊断保留，但不得替代趋势和 KPI 中的平均值主口径。
- 当前并发取 Redis；历史并发取分钟采样聚合。
- 容量卡在筛选变化后重算全局、分组用户级、模型账号和路由四层水位；同一账号被多条路径复用时，账号级只展示一次。
- 当前排队请求、平均等待、今日限流次数必须分别返回或明确标注缺数；平均等待无采样时显示“无近 5 分钟采样”，今日限流次数不能因切换到 1 小时窗口而变成 1 小时数量。
- 采样并发热力格必须同时返回 `actual_concurrency`、`concurrency_limit` 和 `sample_at`，不能只返回百分比。
- `actual_concurrency` 是时间桶内每 20 秒采样中，符合当前筛选和行成员条件的唯一活跃请求数峰值。
- `concurrency_limit` 是同一采样时刻、符合当前筛选和行成员条件的唯一账号生效并发上限之和；同一账号被多条路径复用时只计一次。
- 指定单个模型账号时，所有热力格的分母都等于该账号当时的生效并发上限；分子仍按当前行维度归属请求。
- 时间桶内存在多个采样点时，先逐个计算 `actual_concurrency / concurrency_limit`，取占比最高的采样点作为方块值；悬浮展示的分子、分母和采样时刻必须来自同一点。
- 同一账号被多条路径复用时，并发按账号去重后汇总。
- 无采样时显示“无历史采样”，不能显示 0 或时段系数。
- 每个响应带 `as_of / lag_seconds / complete / warnings / sources / consistency`。
- 数据质量提示必须能追踪到 lag、缺桶、采样缺失、投影未启用或对账差异。

## 6. 交互和视觉规范

### 6.1 视觉

- 页面背景：`#f1f5f9`
- 卡片：白色、`1px #e2e8f0`、`14px` 圆角、轻阴影
- 主色：teal `#14b8a6 / #0d9488`
- 状态色：teal / blue / amber / red
- Hero：teal-50 → white → indigo-50 渐变
- KPI：标题、主值、单位、上下文、sparkline
- 所有状态同时使用文字和颜色，不以颜色作为唯一语义
- 饱和度阈值全局唯一：`< 60%` 健康、`>= 60%` 关注、`>= 80%` 预警、`>= 95%` 过载；热力图、排行、容量卡和 Hero 不得各自定义阈值

### 6.2 响应式

- `>= 1280px`：Hero 横排，趋势/排行双列，链路四列
- `768-1279px`：Hero 换行，趋势与排行改为单列，链路两列
- `< 768px`：所有控件换行；卡片单列；链路使用横向步骤卡；宽表在容器内滚动
- 移动端保留关键 KPI、筛选、容量关注和告警，不要求首屏展示全部趋势
- `prototype.html` 的断点与本节一致：`1279px`、`767px`、`479px`

### 6.3 可访问性

- 所有 Tab 使用 `role="tab"`、`role="tablist"`、`role="tabpanel"`、`aria-selected`、`aria-controls`，并支持左右方向键、Home、End。
- 切换按钮使用 `aria-pressed`；图例按钮可聚焦，被隐藏序列有文字状态。
- 热力格同时具有 `aria-label`、键盘 focus 和数值 tooltip；图表具有文字替代摘要。
- 排行、链路节点、表格行支持 Enter/Space 打开详情。
- 抽屉打开后焦点进入抽屉，Tab 在抽屉内循环，Esc 关闭并恢复原焦点。
- 异步加载容器使用 `aria-busy`，错误块使用 `role="alert"`。

## 7. 加载、空态与错误策略

| 组件 | 加载 | 空态 | 错误 | 缺数 |
|---|---|---|---|---|
| Snapshot | 保留旧值并显示刷新状态 | 显示无匹配对象 | 卡片内错误，不清空其他区块 | 带 warnings |
| 趋势 | 显示已有序列，不覆盖成空 | 无匹配对象说明 | 本图错误 | 缺失桶断点，不补 0 |
| 热力图 | 骨架格 | 无匹配对象 | 本图错误 | 明确“无历史采样” |
| 链路 | 保留当前路径 | 四条链路列显示空态 | 本图错误 | 标注 legacy_inferred |
| 明细 | 表格 loading | 无路径数据 | 本区错误 | 展示数据质量 |
| 告警 | 独立 loading | 无待关注告警 | 独立错误 | 标注无法查询 |

五种状态必须可区分且不可用 0 代填：`loading` 保留已有内容并显示刷新状态；`empty` 显示无匹配对象；`error` 在所属区块内报错；`partial` 显示数据质量与缺口；`unavailable` 显示无采样或暂不可用。

## 9. 生产实现验收门槛

1. 页面结构与四个 Demo 预览图逐区一致，不接受“功能存在即可”。
2. 观测台与同页下钻区共享同一筛选、时间范围和刷新状态。
3. 页面所有组件均覆盖 loading / empty / error / partial / unavailable。
4. 关键流程可在 3 次点击内从告警或排行进入完整路径。
5. 链路四列和详情抽屉始终显示账号唯一绑定模型。
6. 除设计说明外，生产导航不得出现无后端契约的环境选择器。
7. 所有观测接口为 GET；前端不出现写操作入口。
8. 视觉回归至少覆盖 `1440/1280/768/390`、浅色/深色，以及热力图点击后的链路定位状态。
9. 请求数和失败率与事实表对账；无模拟数据进入生产默认状态。
10. 后端 API、RBAC、性能闸门通过后才能删除特性开关或扩大角色范围。

## 10. 确认项

本轮需要确认以下产品选择：

1. 只保留一个页面路由 `/admin/observability`；“调用链路与多维用量”位于压力区下方、告警区上方，并与热力图联动。
2. 生产页面删除无后端契约的“生产环境”选择器，仅保留时间范围和平台说明。
3. “设计说明”只在原型中保留，不进入生产导航。
4. 总览页保持 7 个 KPI，其中最终客户端失败率为主要质量指标。
5. 调用链路固定四列；API Key 只在明细和详情中出现，不作为第五主列。
