# 分组路由候选并发查看功能实施计划

状态：Final — 用户已批准

## 1. 背景

当前 `admin/accounts` 页面能够展示账号当前并发量与账号最大并发量，并通过定时刷新保持数据更新。

分组管理页面中的路由候选已经配置了候选账号及候选级最大并发上限，但缺少独立的并发查看入口。需要增加一个查看功能，让管理员能够按“路由别名—候选—账号”的层级查看各账号当前并发量和该候选的最大并发量。

## 2. 目标

在分组列表操作列增加“查看并发”按钮。

点击按钮后打开独立的并发查看卡片，展示当前分组所有路由候选的容量信息：

```text
路由别名
└── 候选
    └── 账号：当前并发量 / 候选最大并发量
```

并发数据复用 `admin/accounts` 页面已有的刷新思路和数据口径，但不修改账号页面现有逻辑。

## 3. 功能需求

### FR-01：增加查看入口

在分组列表的操作列增加独立按钮。按钮支持权限控制，点击后打开并发查看卡片，不进入分组编辑状态，也不修改分组编辑表单数据。

### FR-02：按路由层级展示

并发查看卡片按照路由别名、候选、候选账号的层级展示。候选保持当前配置顺序，并尽可能展示候选优先级。

### FR-03：多账号分别展示

当一个候选包含多个账号时，每个账号独立展示，不合并成一个总数。

### FR-04：最大并发量展示规则

最大并发量只采用路由候选配置的最大并发上限：已配置时显示具体数值，未配置时显示 `∞`，不使用账号全局最大并发量替代。

### FR-05：当前并发量展示

当前并发量读取账号实时并发数据，并与账号页面使用相同的数据来源和字段口径。展示格式为“当前并发量 / 最大并发量”。

### FR-06：刷新机制

并发查看卡片复用 `admin/accounts` 页面已有的自动刷新节奏，支持现有刷新间隔，默认刷新周期保持一致。卡片打开时启动刷新，关闭时停止刷新，仅刷新并发相关数据，不影响账号页面逻辑。

### FR-07：手动刷新

卡片内提供手动刷新能力。手动刷新不重置当前展开状态、滚动位置或路由结构。

### FR-08：异常状态

处理首次加载、自动刷新、当前并发获取失败、账号暂无并发数据、路由配置为空、候选无账号、卡片关闭和组件卸载等状态。并发数据失败时尽量保留已有路由结构并提示状态。

## 4. 技术范围

### 前端范围

涉及分组列表操作列、并发查看卡片、分组路由数据组装、账号当前并发数据获取、刷新生命周期、中英文文案及相关测试。

### 后端范围

优先复用现有接口和服务。需要确认现有接口是否能提供路由别名、候选顺序、候选账号、候选上限和账号当前并发量；如不足，再增加面向查看功能的查询能力，避免修改已有账号列表接口行为。

## 5. 数据流

```text
点击分组“查看并发”
        ↓
获取分组路由配置
        ↓
解析路由别名、候选顺序、候选账号和候选上限
        ↓
获取候选账号当前并发量
        ↓
按路由别名—候选—账号组装展示数据
        ↓
卡片展示
        ↓
按既有刷新周期更新当前并发量
```

当前并发量基础机制为请求获取/释放 Redis 并发槽位，后端批量读取 Redis 中账号的当前槽位数量，接口返回 `current_concurrency`，前端定时轮询并更新展示。该机制属于定时轮询，不是 WebSocket 主动推送。

## 6. 生命周期要求

打开卡片时加载路由结构和并发数据并启动刷新；卡片打开期间只更新并发数据，避免覆盖路由结构；关闭卡片时停止自动刷新、清理定时器、取消未完成请求并清理临时状态。

## 7. 权限与兼容性

复用分组查看权限或现有权限边界。无权限用户不显示或不可用按钮。不改变分组编辑、分组保存、账号列表、并发计算和路由调度行为，不新增持久化字段。

## 8. 测试计划

覆盖操作列入口、卡片打开关闭、路由别名—候选—账号层级、多账号分别展示、候选上限与 `∞` 展示、并发刷新、异常状态、请求清理、分组编辑隔离、账号页面回归和中英文文案。

## 9. 验收标准

- [ ] 分组操作列存在“查看并发”按钮。
- [ ] 点击后可以打开独立并发查看卡片。
- [ ] 卡片按“路由别名—候选—账号”展示。
- [ ] 一个候选内的多个账号分别展示。
- [ ] 最大并发量使用候选配置值。
- [ ] 未配置候选上限时显示 `∞`。
- [ ] 当前并发量能够正常展示并定时更新。
- [ ] 自动刷新频率与账号页面保持一致。
- [ ] 卡片关闭后不会继续刷新。
- [ ] 刷新异常不会破坏路由结构展示。
- [ ] 不影响分组编辑功能。
- [ ] 不修改 `admin/accounts` 页面现有逻辑。
- [ ] 中英文界面均有对应文案。
- [ ] 相关测试通过。

## 10. 非目标

不将轮询改造成 WebSocket，不修改 Redis 并发槽位设计、账号全局并发量计算、路由调度策略、候选保存规则，也不在编辑表单内部直接展示实时并发。

## 11. 实施阶段

1. 确认现有分组路由接口、账号并发接口和权限边界。
2. 定义“路由别名—候选—账号”的前端展示数据结构。
3. 实现独立并发查看卡片、层级展示、容量格式化和异常状态。
4. 复用账号页面刷新节奏，实现打开、刷新、关闭和请求清理。
5. 补充组件、数据组装及分组/账号页面回归测试。
