# MVP-001: Freeze an executable v4.0 growth contract and crypto baseline

- Protocol: `mvp-list/v1`
- State: `VERIFIED`
- Estimate: `0.5 day`
- Estimate rationale: This is a bounded readiness slice that settles implementation-critical interfaces and produces reproducible crypto fixtures before schema or route work.
- Dependencies: `none`

## Outcome

The sub2api team has one executable v4.0 baseline for the AIWork-facing U interface plus its own M/W interfaces, RBAC permissions, configuration, and external blockers; implementation can start without re-deciding contract semantics.

## Context

`docs/GROWTH_PLAN_AIWORK_API.md` is the frozen field/error/envelope authority. `docs/GROWTH_PLAN_SUB2API_DEV.md` defines the internal service, while the prototype adds a same-origin Web user surface. The repository has no growth implementation yet, uses Go/Gin/Ent, and proves route coverage at startup.

## In Scope

- Record the U, M, and W route matrix and identify `docs/GROWTH_PLAN_AIWORK_API.md` as the only AIWork contract.
- Add a deterministic test-only SM2/SM3/SM4 interoperability fixture and a unit test proving C1C3C2, MAC concatenation, PKCS#7, and payload decoding agree.
- Document a controlled production key-generation and two-project handoff procedure without committing a production private key.
- Define test-only and production-config expectations for `growth.crypto.time_window`, existing `timezone`, U exclusions, M/W RBAC codes, NTP, VPN/IP allowlist, GoldenDB compatibility, and Token fulfillment capability.
- Confirm that `growth_point_pools`, `growth_task_events`, I-face routes, async completion polling, and Web check-in are not implemented.
- Confirm that no AIWork Main, Renderer, preload API, local completion logic, or AIWork page is implemented in this repository.

## Out of Scope

- No production schema, handlers, services, routes, Vue pages, or deployment changes.
- No real production key material or external network configuration.
- No AIWork client implementation or cross-project code change.

## Implementation Notes

- Keep reusable crypto assertions under `backend/internal/service/growth/crypto` and test data under its `testdata/` directory.
- Include all `CRYPTO_*` and `GROWTH_USER_NOT_FOUND` outcomes in the fixture matrix.
- Include `growth.read`, `growth.manage`, `growth.adjust`, `growth.self.read`, and the security-corrected `growth.self.exchange` in the permission decision.
- Resolve conflicting DDL text in favor of `backend/sqlArchiving/182_*` and no edits to `backend/migrations/`.

## Acceptance Criteria

- [x] The committed fixture decrypts to the expected payload while a modified MAC, ciphertext, IV, `kid`, timestamp, nonce, and path produce distinct expected errors.
- [x] The test uses a fixed test key pair only and repository search finds no production private key, `growth_point_pools`, `growth_task_events`, or growth I-face route.
- [x] U/M/W paths, permissions, forbidden fields, production blockers, and the 182 DDL decision are unambiguous in the MVP implementation notes or checked-in test comments.
- [x] The repository contains no new AIWork Main/Renderer code; AIWork remains an external consumer of the U API.
