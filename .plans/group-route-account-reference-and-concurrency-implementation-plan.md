# 分组路由账号引用与候选并发限制实施方案

**状态：Final — user approved**  
**版本：v0.2**  
**日期：2026-08-10**

## 1. 目标与范围

增加两个能力：

1. 在 `admin/accounts` 账号列表和编辑账号卡片中查看账号被哪些分组路由引用。
2. 在编辑分组卡片的路由别名候选区域，为具体候选账号配置最大并发数。

约束：不修改现有 `groups.model_routing` JSON 结构和模型路由选择逻辑；新增关系表保存结构化关系；关系表与 JSON 同步更新；提供可调用的关系重建接口；`max_concurrency` 允许为 `NULL`，表示无限制。

## 2. 整体设计

`groups.model_routing` 仍是模型路由的真实配置。新增派生关系表 `group_model_route_accounts`，一行表示“分组 + 路由别名 + 候选模型 + 账号”。关系表用于账号反向查询和并发配置，不参与原有候选选择逻辑。

分组路由保存时，在同一数据库事务内更新 JSON 和关系表：保留仍存在关系的 `max_concurrency`，删除已不存在关系，新关系默认 `NULL`。同步失败则整体回滚。

## 3. 数据模型

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `group_id` | 分组 ID |
| `route_alias` | 路由别名 |
| `candidate_model` | 候选模型 |
| `account_id` | 账号 ID |
| `max_concurrency` | 最大并发数，可空；`NULL` 表示无限制 |
| `created_at` / `updated_at` | 时间字段 |

增加唯一约束 `(group_id, route_alias, candidate_model, account_id)`，并为 `account_id`、`group_id`、路由查询建立索引。关系表保存账号 ID，不保存账号名称。

兼容现有旧格式 `{"test":[1,2]}` 和候选对象格式 `{"test":[{"model":"deepseek-v4-pro","account_ids":[1,2]}]}`，复用现有 JSON 解析逻辑。

## 4. 用户功能

### 4.1 分组编辑

在编辑分组卡片的路由别名候选区域，在“优先级”输入框旁增加“最大并发”输入框。

- 输入正整数：设置限制。
- 留空：保存为 `NULL`，表示无限制。
- `0` 不允许保存。
- 只允许配置当前候选中的账号。

### 4.2 账号列表与详情

在 `admin/accounts` 表格新增“被分组路由引用”列，展示分组名和路由别名；引用过多时显示摘要及总数，无引用时显示“未被引用”。

在编辑账号卡片最下方增加只读“分组路由引用”区域，展示分组名称、路由别名、候选模型和最大并发数。账号页面不修改该配置。

### 4.3 关系重建

提供管理员接口：

- `POST /api/v1/admin/groups/:group_id/model-route-references/rebuild`
- `POST /api/v1/admin/model-route-references/rebuild`

分别支持单组和全量重建。重建以 JSON 为准，保留已有关系的并发配置，删除失效关系，新增关系默认 `NULL`，结果可重复且幂等。

## 5. Redis 与请求限流

数据库只保存并发配置，Redis 保存配置缓存和实时并发数。配置缓存状态必须区分：Key 不存在、`unlimited`、正整数。查不到关系或 `max_concurrency IS NULL` 时缓存明确的 `unlimited`，避免每次请求回源数据库。

分组路由配置或并发配置提交成功后，主动更新对应 Redis 配置；改为 `NULL` 时写入 `unlimited`，不能只删除 Key。Redis 更新失败需记录并重试或补偿。

请求确定最终候选账号后，以 `group_id + route_alias + candidate_model + account_id` 生成 Redis Key。具体限制使用 Redis 原子操作获取名额，调用完成、失败或超时后释放；占用设置 TTL，防止异常请求永久占用。超过上限默认直接拒绝，不排队。多实例共享 Redis。

## 6. 接口与事务

账号引用查询：`GET /api/v1/admin/accounts/:id/model-route-references`，返回 `group_id`、`group_name`、`route_alias`、`candidate_model`、`max_concurrency`。

并发配置更新接口按现有分组路由 API 风格实现，至少接收 `route_alias`、`candidate_model`、`account_id`、可空的 `max_concurrency`，保存前校验关系存在。

分组路由更新流程：

```text
begin transaction
  更新 groups.model_routing
  删除该分组旧关系
  写入新关系，并保留已有 max_concurrency
commit
更新受影响 Redis 配置缓存
```

数据库事务失败时 JSON 和关系表均不生效；数据库成功而 Redis 更新失败时记录错误并补偿，数据库配置仍为最终来源。

## 7. 兼容、迁移与运维

上线后先创建关系表，再调用全量重建接口初始化历史数据，校验 JSON 与关系表数量后开放页面功能。重建接口用于历史数据初始化、异常修复和运维校准。

需记录关系同步失败、重建失败、Redis 更新失败、并发拒绝次数、Redis 命中率和异常释放情况。关系重建和配置更新应具备权限校验、参数校验和审计日志。

## 8. 验收标准

- 账号列表新增引用关系列，编辑账号卡片底部展示完整引用关系。
- 分组编辑卡片候选区域在优先级旁可配置最大并发。
- 留空保存为 `NULL`，查询不到或为 `NULL` 均不限制。
- 分组路由新增、修改、删除时关系表同步更新，失败可回滚。
- 单组和全量重建接口可重复执行，并保留既有并发配置。
- 配置更新后 Redis 立即使用新值；无限制状态缓存为 `unlimited`。
- 达到限制后请求被拒绝；完成、失败、超时后占用可释放。
- 多实例共同遵守同一上限。
- 现有 JSON 结构和模型路由选择行为保持兼容。

## 9. 实施顺序

1. 创建关系表、唯一约束和索引。
2. 实现 JSON 解析、关系同步及事务接入。
3. 实现单组和全量重建接口，初始化历史数据。
4. 实现账号列表列和编辑账号卡片底部展示。
5. 实现分组候选区域的最大并发输入和保存接口。
6. 实现 Redis 配置缓存、`unlimited` 状态和配置刷新。
7. 接入请求级 Redis 并发控制、TTL 回收和监控。
8. 完成单元、集成、迁移和端到端验证。

## 10. 默认决策

- 超过上限直接拒绝，不排队。
- `NULL` 表示无限制，`0` 禁止保存。
- 并发配置只在编辑分组页面修改，账号页面只读展示。
- Redis 配置缓存和实时计数使用不同 Key。
- 数据库是配置最终来源，Redis 是高频访问缓存和运行时计数存储。

## 11. 追踪关系

| 目标 | 模块 | 验收 |
|---|---|---|
| 查看账号被引用关系 | 关系表、账号列表、账号编辑卡片 | 账号页面正确展示分组/路由/候选 |
| 保持关系同步 | 分组保存事务、重建接口 | 更新、删除、重建结果一致 |
| 配置候选并发 | 分组编辑候选区域、关系表 | 可保存正整数或 `NULL` |
| 执行并发限制 | Redis 配置缓存、原子计数、TTL | 上限生效且请求结束后释放 |
