# 模型路由候选并发分配与配置管理改造 Plan

状态：Final — user approved

## 1. 背景

当前系统同时存在账号级并发限制和候选级并发限制，但候选并发配置没有受到账号总并发的额度约束，也不会随着账号并发变化自动调整。

本次改造将候选并发理解为从账号总并发中分配出去的子额度，但只改造配置、校验、展示和同步逻辑，不修改现有请求执行时的并发限制机制。

## 2. 目标与非目标

### 2.1 目标

- 保证具体候选并发分配总和不超过账号总并发；
- 账号并发变化时自动调整已有候选并发分配；
- 在分组页面展示候选并发占账号并发的比例；
- 在账号页面展示分组路由引用、候选并发数及占比；
- 正确处理账号并发为 `0` 时的“不限制”语义；
- 保持现有账号级和候选级请求限流逻辑不变。

### 2.2 非目标

不改动请求候选选择、候选槽位抢占释放、账号槽位抢占等待释放、候选降级规则、Redis 槽位算法和全局并发过滤。

## 3. 规则与数据含义

候选关系维度为：

```text
分组 + 路由别名 + 候选模型 + 候选账号
```

`group_model_route_accounts.max_concurrency` 存储具体整数或 `null`：

- 具体整数：候选级并发上限，并参与账号额度分配；
- `null` 或关系记录中查不到配置：候选级不限制，不参与账号额度分配；
- 候选为 `null` 时仍然受到账号自身总并发限制。

账号 `concurrency` 规则：

- 大于 0：账号总并发上限；
- 等于 0 或负数：按现有执行逻辑视为账号级不限制；
- 账号并发字段本身不使用 `null` 表示无限制。

数据库保存绝对并发数，页面动态计算：

```text
候选占比 = 候选并发数 / 账号总并发数 × 100%
```

账号并发为 0 或负数时，比例显示为“不适用（账号不限）”。

## 4. 配置校验与自动调整

账号并发大于 0 时，只统计有具体数字的候选：

```text
具体候选并发总和 <= 账号总并发
```

分组编辑保存时，后端重新读取账号当前并发和该账号全部候选分配并校验；超限时拒绝保存并返回明确错误。

账号并发从正数变为正数时，按比例缩放具体候选分配，先向下取整，再按小数部分从大到小分配余数，确保总和不超过新并发数。

账号并发从 0 变为正数时：如果已有具体候选总和不超过新并发则保持不变；如果超出则按当前分配比例收敛；`null` 候选不变；不自动给无分配候选分配额度。

账号并发从正数变为 0 时，保留具体候选并发，不做放大；账号级变为不限制，候选级限制仍然保留。

账号并发为 0 时允许具体候选分配总和不受账号总并发上限约束，但页面不计算比例。

## 5. 一致性与缓存

账号并发变更与候选并发重算在同一数据库事务中完成：锁定账号、读取旧配置、计算新配置、校验、更新账号和候选关系、提交事务。提交成功后再同步相关 Redis 配置；数据库失败不更新 Redis，Redis 更新失败记录日志并允许后续按数据库重载。

分组编辑候选并发也必须在读取、校验、更新之间提供事务或等价并发保护，避免并发修改导致超限。

## 6. 页面改造

分组编辑候选旁展示最大并发、占账号并发比例和账号已分配额度。候选为 `null` 时显示“无限制（不参与分配）”；账号为 0 时显示“账号并发：不限，占比：不适用”。

账号列表和编辑账号页面的分组路由引用展示分组、路由、候选并发、占比和已分配额度；`null` 或缺少配置时明确显示“无限制 / 不参与分配”。保留现有彩色标签、列宽限制、标签间换行和展开能力。

## 7. 验收标准

- 账号并发大于 0 时，具体候选并发总和不能超过账号并发；
- `null` 或缺少配置的候选不参与总和和比例计算；
- 账号并发为 0 时不做总和上限校验，比例显示不适用；
- 0 与正数互相切换时按规则保留或收敛候选配置；
- 正数变更为正数时按比例缩放并保证舍入后不超限；
- 分组页面、账号列表、编辑账号页面展示数字、比例和无限制状态；
- 配置更新具备事务一致性并同步 Redis；
- 现有请求级账号和候选限流行为不发生变化。
